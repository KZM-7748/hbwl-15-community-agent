# 怎么发给别人看

**先说最关键的一点**：这个智能体是一个**正在运行的服务**，不是一张图片或一个文件。
别人能不能打开，取决于**他在哪个网络里**。

| 对方在哪 | 能不能打开 | 用什么地址 |
|---|---|---|
| **同一个 WiFi / 局域网**（家里、宿舍、同一间办公室） | ✅ 能 | `http://192.168.x.x:8080/student` |
| **校园网内**（一体机部署后） | ✅ 能 | 部署机在校园网内时的地址 |
| **校外、外地、手机流量** | ❌ 不能 | 需先做公网方案（见第五节） |

---

## 一、最快的办法：生成分享页

在项目文件夹里运行：

```bash
node scripts/share.js
```

会生成 **`分享给他人.html`**，把它发给对方（微信、QQ 传文件都可以）。
对方用浏览器打开，就能看到：

- ✅ 服务当前是否在运行
- 📱 **可扫码的二维码**（手机扫码直接进学生端）
- 🔗 可点击的网址
- ⚠️ 打不开时按顺序排查的步骤

> 这个文件是**自动生成**的，里面的 IP 和二维码都指向当前这台机器。
> 如果换了网络或重启后 IP 变了，**重新运行一次** `node scripts/share.js` 即可。

---

## 二、直接发网址（最简单）

如果对方就在你旁边，直接把网址发给他：

```
http://192.168.1.2:8080/student
```

**这个地址怎么来的？** 启动服务时窗口会打印：

```
★ 分享给同学（需在同一网络）：
  http://192.168.1.2:8080/student
```

> ⚠️ **IP 可能会变**。家庭宽带 / DHCP 环境下，重启或断网重连后 IP 会变
> （实测中曾从 `192.168.1.2` 变成 `192.168.1.3`）。
> 变了就重新看启动窗口，或重新生成分享页。

---

## 三、手机扫码（最方便）

**方式一：看分享页**
运行 `node scripts/share.js`，用手机扫分享页上的二维码。

**方式二：看一体机大屏**
学生端左侧「手机端入口」有二维码，同学直接扫。

**方式三：让手机浏览器打开学生端**
在电脑上打开学生端，把二维码放大（点「放大二维码」），手机对着屏幕扫。

> 手机必须和电脑连**同一个 WiFi**。

---

## 四、对方打不开？按这个顺序查

这是最常见的四个原因，**按顺序排查**：

### 1. 服务是不是没启动？

看启动窗口在不在、有没有报错。或运行：

```bash
node scripts/deploycheck.js
```

### 2. 是不是不在同一个网络？

- 手机连的是不是和电脑**同一个 WiFi**？
- 对方是不是在校外 / 用手机流量？→ 那肯定打不开，见第五节
- 有些校园网/公司网**隔离了设备**（AP 隔离），同一 WiFi 也互相访问不了

### 3. 防火墙是不是拦了？（**最常见**）

Windows 防火墙默认阻止外部访问。**以管理员身份**运行：

```bat
netsh advfirewall firewall add rule name="15栋社区智能体" dir=in action=allow protocol=TCP localport=8080
```

> 右键「终端」→「以管理员身份运行」，粘贴上面这行回车即可。
> 这一步是整个分发环节里**最容易漏**的。

### 4. 网址抄错了？

IP 变了但还在用旧地址。重新看启动窗口，或重新生成分享页。

## 五、要给校外的人看（需要额外处理）

校外的人**无法访问** `192.168.x.x` 这类局域网地址。三种办法：

### 方案 A：临时演示（最快，几分钟）

用 Cloudflare Tunnel，把本机服务映射成公网网址：

```bash
cloudflared tunnel --url http://localhost:8080
```

会输出一个 `https://xxx.trycloudflare.com` 的网址，**任何人**都能打开。
关掉窗口即失效。

- 下载：<https://github.com/cloudflare/cloudflared/releases>
- ⚠️ 公网可访问 = **任何人都能打开教师端**，务必先改默认口令
- ⚠️ 你的电脑必须一直开着

### 方案 B：部署到校园网内的机器

这是**最推荐**的正式方案——数据不出校，同学用校园网即可访问。
详见 **部署指南.md** 第一节。

### 方案 C：部署到云平台

Render / Railway / Fly.io 等。注意免费档通常无持久磁盘，教师端内容会丢。
详见 **部署指南.md** 第三节。

## 六、发给不同对象的建议

| 对象 | 发什么 | 说明 |
|---|---|---|
| **同学** | 学生端网址 或 二维码 | `http://x.x.x.x:8080/student` |
| **辅导员/老师** | 分享页 + 教师端口令 | 教师端要口令，口令单独告知 |
| **学院领导/毛老师** | 分享页 + 一句话说明 | 建议先自己演示一遍 |
| **校外的人** | 公网网址（方案 A/B/C） | 局域网地址对他无效 |

### 给老师演示的建议

1. **提前跑一遍**，确认能打开（别到现场才发现防火墙没放行）
2. **准备好真实问题**，比如「宿舍东西坏了怎么报修」「图书馆开放时间」
3. **主动说明边界**：知识库有 9 条「待确认」，需学院确认；通知日期等需学院发布
4. **说明数据来源**：53 条已核实内容来自 13 个官方渠道，回答末尾有来源标注

---

## 七、一句话总结

**同一 WiFi → 直接发网址；校外 → 先做公网方案。**

最简单的做法：运行 `node scripts/share.js`，把生成的 `分享给他人.html` 发过去。
对方打不开，九成是**防火墙没放行**，让管理员跑一次那条 `netsh` 命令即可。
