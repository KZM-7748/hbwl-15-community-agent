# 部署指南

15栋一站式社区智能体有三种部署方式。**学院一站式社区定位下，方式一（校园网）是推荐做法**；
方式二适合临时演示；方式三适合要长期稳定运行且不想维护服务器。

> **重要前提**：程序必须**通过服务器访问**（`http://...`），
> 不能直接双击 `public/` 里的 html 文件——那样样式和校徽都会加载失败（详见 README 第一节）。

---

## 方式一：部署在校园网内的机器上（推荐）

这是最符合「一站式社区」定位的做法：机器在校园网内，同学用校园网即可访问，**数据不出校**。

### 1. 准备机器

一台放在校园网内、且**长时间不关机**的设备：

| 选择 | 说明 |
|---|---|
| **15栋一楼一体机** | 现成就有，屏幕还能展示二维码；但一体机常插电运行，需确认不放长假关机 |
| 学院闲置电脑/旧笔记本 | 功耗低，适合长驻 |
| 学院向信息化中心申请的服务器 | 最稳，可获得校内域名 |

**这台机器必须在校园网内**，不能是宿舍的宽带（`192.168.1.x` 段且网关是 `192.168.1.1` 通常不是校园网）。

### 2. 安装与启动

把整个 `hbwl-15-community-agent` 文件夹拷到这台机器上，安装 Node.js（[nodejs.org](https://nodejs.org)，勾选「Add to PATH」），然后双击：

```
启动.bat
```

启动窗口会直接给出**可分享的网址**：

```
★ 分享给同学（需在同一网络）：
   http://192.168.1.2:8080/student
```

### 3. 开放防火墙（关键，否则别人打不开）

Windows 防火墙默认阻止来自其他机器的连接。**必须以管理员身份**运行下面的命令：

```bat
netsh advfirewall firewall add rule name="15栋社区智能体" dir=in action=allow protocol=TCP localport=8080
```

复制到记事本存成 `放行防火墙.bat`，右键「以管理员身份运行」最省事。

> 这一步是整个部署里最容易漏的。启动后服务本身正常，但不能被其他机器访问。
> 用手机连上同一 WiFi，访问打印出来的网址，就是最快的验证。

### 4. 确认能访问并分享

在**另一台设备**（手机/同学的电脑）上访问启动窗口给出的网址。能看到欢迎页就说明通了。

学生端右下角（侧栏「手机端入口」）会自动显示**二维码**，同学扫码即可在手机上打开，功能与大屏一致。

### 5. 设置开机自启动

避免每次重启都要手动开。两种方式任选：

**任务计划程序**（推荐，重启后自动运行且用户无需登录）：

1. `Win+R` 输入 `taskschd.msc`
2. 右侧「创建任务」
3. 「常规」：名称填 `15栋社区智能体`，勾选「不管用户是否登录都要运行」+「使用最高权限运行」
4. 「触发器」：新建 → 开始任务选「登录时」
5. 「操作」：启动程序
   - 程序或脚本：`node.exe` 的完整路径（如 `C:\Program Files\nodejs\node.exe`）
   - 添加参数：`server.js`
   - 起始于：`C:\`（填写项目文件夹的绝对路径，如 `C:\hbwl-15-community-agent`）
6. 「设置」：勾选「如果任务失败，按以下频率重新启动」（如 5 分钟）
7. 确定，输入当前用户密码

**启动文件夹**（简单，但需用户先登录）：

1. `Win+R` 输入 `shell:startup`
2. 在该文件夹放入一个快捷方式，目标指向 `启动.bat` 的完整路径

### 6. 部署自检

在目标机器上运行：

```bash
node scripts/deploycheck.js
```

它会检查 Node 版本、是否监听 `0.0.0.0`、端口占用、可分享的网址、防火墙状态、IP 是否动态、教师端口令是否仍为默认值，并**对每一项问题给出可直接复制的修复命令**。

## 方式二：临时公网访问（演示用）

适合给校外老师/同学演示，或临时测试。**你的电脑必须保持开机且不能睡眠**。

### Cloudflare Tunnel（免费、无需备案）

在装有项目的电脑上运行：

```bash
cloudflared tunnel --url http://localhost:8080
```

会输出一个 `https://xxx-xxx-xxx.trycloudflare.com` 的公网网址，任何人可访问。`Ctrl+C` 即失效。

**下载**：<https://github.com/cloudflare/cloudflared/releases>。

**注意**：
- 公网可访问 = 任何人都能打开教师端，务必先改掉默认口令
- 关机/断网即失效，仅适合演示
- 国内访问 Cloudflare 偶有不稳定

### Ngrok

```bash
ngrok http 8080
```

有免费额度，生成的 `https://xxxx.ngrok-free.app` 也可直接访问，但免费版有连接数限制。

## 方式三：部署到云平台（长期稳定）

适合希望长期稳定运行、不必维护实体机器。**注意：以下平台的免费档通常不含持久磁盘，教师端发布的通知会在重启后丢失。**

| 平台 | 免费档 | 是否适合 |
|---|---|---|
| **Render** | Web Service，免费档会休眠，首次访问慢 | 需付费档才有持久磁盘 |
| **Railway** | 有试用额度，含持久卷 | 适合，超额度后付费 |
| **Fly.io** | 有免费额度，含 Volume | 适合，需绑定信用卡 |
| **Vercel / Netlify** | 纯 Serverless | **不适合**：程序要读写本地文件，Serverless 文件系统是临时的 |
| **GitHub Pages** | 纯静态托管 | **不适合**：只能托管静态 HTML，跑不了 Node 服务 |

### 以 Render 为例的要点

1. 用 GitHub 账号登录 Render
2. New → Web Service → 选择本项目仓库
3. Build Command：`npm install`（本项目实际无需依赖）
4. Start Command：`node server.js`
5. 环境变量：`TEACHER_PIN` 设一个强口令，`PORT` 由平台注入

> **必须把 `data/_logs/`、`data/*.json` 加入持久磁盘**，否则重启后教师端编辑的内容全部丢失。
> 免费档通常没有这项，这也是我推荐方式一的主要原因。

## 无论哪种方式，都要做的三件事

### 1. 立即修改教师端口令

默认口令 `hbuas2026` 是公开可猜的。登入教师端前改掉：

编辑 `data/_config.json`：

```json
{
  "teacherPin": "改成你自己的强口令",
  "siteName": "15栋一站式社区智能体",
  "notice": ""
}
```

或设置环境变量（优先级更高）：

```bat
set TEACHER_PIN=你的强口令
```

### 2. 备案与合规（公网部署时）

按工信部规定，公网 HTTP 服务需要**域名 + ICP 备案**。高校通常以学校主体统一备案，**请与学院信息化中心/网络中心确认**：
- 校园网内 IP 访问是否需要登记
- 能否申请校内域名（如 `15shequ.hbuas.edu.cn`）
- 公网部署由哪一级审批

### 3. 定期备份知识库

整个 `data/` 目录（除 `_logs/`）就是全部内容资产。定期复制一份到网盘或 U 盘即可恢复。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动窗口一闪就过，或提示端口被占 | 8080 被别的程序占用 | 用 `set PORT=8081` 后重新启动，访问 `http://localhost:8081` |
| 本机正常，手机上打不开 | ① 不在同一网络 ② 防火墙拦了 | 见本文 3. 开放防火墙 |
| 校园网内打不开 | 机器不在校园网；网关是 `192.168.1.1` 通常是家用路由器 | 换到校园网内的机器上部署 |
| 重启后网址变了 | IP 是 DHCP 动态分配 | 在路由器/网卡上固定 IP，或向信息化中心申请静态 IP |
| 页面无样式、校徽显示为裂图 | 直接双击了 html 文件 | 通过 `http://` 地址访问，见 README 第一节 |
| 想换端口 | 默认 8080 | `set PORT=80` 可去掉 `:8080`，www 默认端口 |
