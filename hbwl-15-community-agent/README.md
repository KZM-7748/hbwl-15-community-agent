# 15栋一站式社区智能体

**湖北文理学院 · 计算机工程学院**

面向 15 栋一站式学生社区的 AI 智能体，覆盖**通知答疑**与**活动辅助**两大场景，
提供**大厅一体机**与**手机端**双入口，并区分**学生端**与**教师端**两种角色。

> **视觉规范遵循学校 VI**：主色取自官方校徽（深绿 `#286840` / 亮绿 `#009048`），
> 页头使用官方校徽与校标，校训「淡泊明志 宁静致远」贯穿界面。
>
> **知识库基于官方公开信息构建**：62 条知识中 53 条已从 13 个官方渠道核实并标注来源，
> 9 条为项目建设/示例内容并明确标记「待确认」。详见第八节。

## 一、快速开始

### 方式一：双击启动（推荐，适合一体机与不熟悉命令行的老师）

双击项目文件夹里的 **`启动.bat`**，它会自动启动服务并打开浏览器。

> 关闭那个黑色窗口 = 停止服务。

### 方式二：命令行

```bash
cd hbwl-15-community-agent
node server.js
```

启动后终端会打印访问地址与教师端口令：

```
入口页（选角色）： http://localhost:8080
学生端：           http://localhost:8080/student
教师端：           http://localhost:8080/teacher
手机端（同网）：   http://192.168.x.x:8080
教师端口令：hbuas2026
```

> **无需安装任何依赖**，仅需 Node.js 18+。知识库为本地 JSON 文件，断网可用。

### ⚠️ 不要直接双击 public 文件夹里的 html 文件

**这是最常见的错误。** 直接双击 `index.html` / `student.html` / `teacher.html`
会用 `file://` 协议打开，此时样式表与校徽图片全部无法加载，
页面会显示成没有格式的纯文本样子（图片位置显示为裂图）。

**必须先启动服务，再通过 `http://localhost:8080` 访问。**
如果误用了 `file://` 方式打开，页面顶部会自动显示红色提示告知正确做法。

### 三个入口

| 入口 | 路径 | 用途 |
|---|---|---|
| **入口页** | `/` | 角色选择（学生端 / 教师端） |
| **学生端** | `/student` | 问答：查通知、咨询办事流程、看活动 |
| **教师端** | `/teacher` | 数据看板 + 知识库维护（需口令） |

一体机建议直接打开 `/student` 并全屏（F11），省去角色选择步骤。

### 手机端入口（二维码）

学生端侧栏会自动显示**二维码**（指向 `.studentUrl`），同学扫码即可在手机上打开，
功能与大屏完全一致——对应「大厅有终端，人人有手机端」。

服务会自动判断对外地址：
1. 设了环境变量 `PUBLIC_URL` → 用它（学院配了域名时最省事）
2. 否则用请求的 `Host`；若访问方是 `localhost`，自动替换为**局域网 IP**，方便直接分享
3. 兜底用本机第一个局域网 IP

启动窗口也会直接打印可分享的网址：

```
★ 分享给同学（需在同一网络）：
  http://192.168.1.2:8080/student
```

> 单机使用时那个 IP 也可能是 `localhost` 或虚拟网卡地址，
> 以启动窗口打印的「分享给同学」那行为准。

### 部署到校园网

**详见 [部署指南.md](部署指南.md)**，包含三种方式（校园网内机器 / 公网临时演示 / 云平台）
以及防火墙放行、静态 IP、开机自启、ICP 备案注意事项。

部署到新机器后，先跑一次部署自检：

```bash
node scripts/deploycheck.js
```

它会检查服务监听、端口占用、防火墙、IP 是否动态、教师端口令等，
并对每个问题给出**可直接复制的修复命令**。

### 部署到社区一体机

1. 把整个 `hbwl-15-community-agent` 文件夹拷到一体机
2. 安装 Node.js 18+（[官网下载](https://nodejs.org)）
3. 双击 **`启动.bat`**（或执行 `node server.js`）
4. 浏览器访问 `http://localhost:8080/student`，按 `F11` 全屏
5. **以管理员身份放行防火墙**，否则其他机器访问不了：
   ```bat
   netsh advfirewall firewall add rule name="15栋社区智能体" dir=in action=allow protocol=TCP localport=8080
   ```
6. 设置开机自启（见部署指南第 5 节）

## 三、技术方案

### 为什么选择离线检索

社区一体机的实际约束是：**可能没有稳定外网、没有 GPU、交付后需要长期免维护**。

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯大模型 API | 回答灵活 | 需外网+API Key+费用；断网即废；**可能编造办事流程** | ✗ 不适合 |
| 向量检索 | 语义泛化好 | 需模型文件与算力；中文小语料收益有限 | ✗ 过重 |
| **BM25 关键词检索** | 零依赖、毫秒级、可解释、断网可用 | 不懂同义改写 | **✓ 采用** |

对社区服务场景，**准确性比灵活性更重要**——一个编造的办事流程会让同学白跑一趟。
离线检索的每条回答都可追溯到具体知识条目与官方来源。

同时**预留大模型增强开关**：配置 `LLM_API_KEY` 即启用，不配置则纯离线运行。

### 检索实现

中文没有空格分词，采用**字符二元组（bigram）为主、单字为辅**：

```
「自习室怎么预约」
  → 二元组：自习 习室 室怎 怎么 么预 预约   （主要信号）
  → 单字：  自 习 室 怎 么 预 约            （辅助召回，权重 ×0.25）
```

**关键调优**：单字必须降权。否则「今天天气怎么样」会因「怎/么/样」匹配到
「自习室可以占座吗？东西放在座位上会**怎样**」而被误判。
降权后无关问题得分从 8.41 降到 1.18，与正常问题（3.4 以上）形成清晰空档，
据此标定置信度阈值 `2.0`。

### 意图路由

三级处理：

1. **紧急通道**——仅匹配**已发生的受损事实**（被骗、着火、受伤）与**明确求助动作**（救命、快报警）
2. **列表通道**——「最近有什么活动」走活动清单，优先于 FAQ 检索
3. **检索通道**——BM25 检索，置信度不足则走兜底引导

### 关于「句式相似但主题不同」的问题（重要说明）

有一类问题词面检索无法可靠处理，例如：

| 提问 | 检索到的条目 | 问题 |
|---|---|---|
| 怎么办理校园卡 | 图书馆怎么借书 | 靠「校园卡」三字命中，主题不同 |
| 四六级报名时间 | 活动与计划列表 | 「报名」触发活动意图 |

本项目**实测过两种更复杂的判据，都因误伤正常问题而放弃**：

- **优势比**（Top1 领先 Top2 的幅度）：正常问题可低至 0.015，缺口问题可高达 0.80，分布重叠
- **主题词整词覆盖**：正常问题误判 2/25（「学校的校历在哪看」被误拦），
  且「四六级报名时间」被误标为缺口

**最终方案是补齐内容而非加判据**：把真实可查的信息补进知识库
（校园卡、宿舍熄灯、选课、转专业、助学贷款、奖学金、校历、校区、电动车、体育场馆等 10 条），
使 12 个测试缺口中的 11 个得到真实回答。剩余无法查询的（如校车时刻表）如实走兜底。

> 这个取舍的理由：加判据会让正常问题被误答成「我不知道」，
> 而同学会因此以为知识库里什么都没有——**误拦比漏答的代价更高**。
> 真正的解法是持续补录内容，教师端「未命中问题」看板就是为此设计的。

## 五、教师端使用

### 登录

访问 `/teacher`，输入口令（默认 `hbuas2026`）。
会话令牌保存在浏览器 `sessionStorage`，8 小时过期，关浏览器即失效。

**部署后请立即修改口令**：编辑 `data/_config.json` 的 `teacherPin`，
或用环境变量 `TEACHER_PIN` 指定。

### 发布通知

教师端 →「通知公告」→「+ 新增」，填写标题、分类、正文、检索关键词。

> **检索关键词是命中率的关键。** 例如「报修」这条把「微后勤、漏水、灯、门锁、断电」
> 都写进关键词，同学用哪种说法都能问到。

也可以直接编辑 `data/notices.json`：

```json
{
  "id": "n009",
  "title": "期末考试安排公布",
  "category": "教学通知",
  "date": "2026-10-20",
  "publisher": "计算机工程学院教务办",
  "priority": "high",
  "pinned": true,
  "deadline": "2026-10-25",
  "verified": true,
  "sourceId": "s009",
  "tags": ["考试", "期末", "安排"],
  "content": "期末考试安排已公布，请同学们登录教务系统查询…"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | 标题，检索权重最高 |
| `content` | ✓ | 正文 |
| `verified` | ✓ | **`true` 表示已核实**（须填 `sourceId`）；`false` 显示「待确认」徽章 |
| `sourceId` | 条件 | `verified:true` 时必填，须存在于 `sources.json` |
| `tags` | | **检索关键词**，同学可能用到的说法都放进来 |
| `pinned` / `deadline` | | 置顶 / 截止日期 |

### 审核待确认内容

教师端 →「待确认」→ 点「去核实」→ 编辑内容 → 把「核实状态」改为**已核实**
→ 填写**来源编号**（如 `s008`）→ 保存。

> 系统会强制校验：标为「已核实」必须有有效 `sourceId`，否则拒绝保存。
> 这是防止「把编造内容伪装成官方信息」的机制。

### 看板数据从哪来

同学每次提问都会记录到 `data/_logs/queries-YYYY-MM-DD.jsonl`，
教师端看板据此统计高频问题与未命中问题。

> **隐私说明**：日志只记录问题原文与意图分类，**不记录任何身份信息**
> （无 IP、无学号、无会话 ID）。可在教师端清空日志，或直接删除 `data/_logs/` 目录。

### 自检

改动知识库或代码后运行：

```bash
node scripts/selfcheck.js
```

49 项测试覆盖事实问答、意图路由、边界处理与**数据溯源完整性**。

### 开机自启（Windows 一体机）

**任务计划程序**（推荐）：

1. 「任务计划程序」→「创建任务」
2. 常规：勾选「不管用户是否登录都要运行」「使用最高权限运行」
3. 触发器：新建 →「登录时」
4. 操作：启动程序
   - 程序：`node.exe` 完整路径（如 `C:\Program Files\nodejs\node.exe`）
   - 参数：`server.js`
   - 起始于：`C:\path\to\hbwl-15-community-agent`
5. 设置：勾选「如果任务失败，按以下频率重新启动」

## 九、接口文档

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| `POST` | `/api/ask` | — | 提问。Body: `{"question": "..."}` |
| `GET` | `/api/notices` | — | 通知列表 |
| `GET` | `/api/activities` | — | 活动列表 |
| `GET` | `/api/venues` | — | 场所列表 |
| `GET` | `/api/faqs` | — | 问题清单 |
| `GET` | `/api/stats` | — | 统计（含核实/待确认条数） |
| `GET` | `/api/health` | — | 健康检查 |
| `POST` | `/api/teacher/login` | — | 教师端登录，返回令牌 |
| `POST` | `/api/teacher/logout` | ✓ | 登出 |
| `GET` | `/api/teacher/dashboard?days=7` | ✓ | 数据看板 |
| `GET` | `/api/teacher/sources` | ✓ | 来源清单 |
| `GET` | `/api/teacher/content/:kind` | ✓ | 内容列表 |
| `POST` | `/api/teacher/content/:kind` | ✓ | 新增 |
| `PUT` | `/api/teacher/content/:kind/:id` | ✓ | 修改 |
| `DELETE` | `/api/teacher/content/:kind/:id` | ✓ | 删除 |
| `DELETE` | `/api/teacher/logs` | ✓ | 清空问答日志 |

`:kind` 取值：`notices` / `activities` / `faqs` / `venues`
鉴权方式：请求头 `Authorization: Bearer <token>`

```json

  "text": "**学校的报警电话是多少？**\n\n…",
  "intent": "retrieval",
  "verified": true,
  "sources": [{ "id": "f006", "type": "faq", "title": "学校的报警电话是多少？" }],
  "cards": [{ "id": "f006", "type": "faq", "title": "…", "verified": true }]
}
```

## 十、后续可扩展方向

1. **接入真实报名系统**——目前报名为指引式，可对接学院表单实现真报名
2. **二维码生成**——一体机动态生成当前 IP 的二维码，方便手机扫码
3. **多轮对话**——当前为单轮问答，可加会话上下文支持追问
4. **热点问题推送**——据看板数据在首页突出高频问题
5. **语音输入**——一体机加装麦克风后用 Web Speech API 实现语音提问
6. **接入企业微信/公众号**——复用 `/api/ask` 接口
7. **定期同步官方通知**——抓取学院官网「学工动态」自动入库（需学院授权）
8. **多角色扩展**——如辅导员端（查看本班学生关注点）

## 十一、交付说明

- **知识库已基于官方公开信息填充**，53 条已核实内容可直接使用。
- **9 条「待确认」内容**需学院确认后，在教师端把「核实状态」改为已核实并填写来源编号。
- **教师端口令请在部署后立即修改**（`data/_config.json` 或环境变量 `TEACHER_PIN`）。
- **问答日志不含身份信息**，仅记录问题原文与意图分类。
- **首次部署**建议先在电脑上跑通，确认问答正常后再拷到一体机。
- **上线前建议**：由学院学工办通读一遍知识库，确认无误后正式发布。
