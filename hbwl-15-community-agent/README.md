# 15栋一站式社区智能体

**湖北文理学院 · 计算机工程学院**

面向 15 栋一站式学生社区的 AI 智能体，覆盖**通知答疑**与**活动辅助**两大场景，
提供**大厅一体机**与**手机端**双入口，并区分**学生端**与**教师端**两种角色。

> **视觉规范遵循学校 VI**：主色取自官方校徽（深绿 `#286840` / 亮绿 `#009048`），
> 页头使用官方校徽与校标，校训「淡泊明志 宁静致远」贯穿界面。
>
> **知识库基于官方公开信息构建**：62 条知识中 53 条已从 13 个官方渠道核实并标注来源，
> 9 条为项目建设/示例内容并明确标记「待确认」。详见第八节。

## 一、快速开始

### 方式一：双击启动（推荐，适合一体机与不熟悉命令行的老师）

双击项目文件夹里的 **`启动.bat`**，它会自动启动服务并打开浏览器。

> 关闭那个黑色窗口 = 停止服务。

### 方式二：命令行

```bash
cd hbwl-15-community-agent
node server.js
```

启动后终端会打印访问地址与教师端口令：

```
入口页（选角色）： http://localhost:8080
学生端：           http://localhost:8080/student
教师端：           http://localhost:8080/teacher
手机端（同网）：   http://192.168.x.x:8080
教师端口令：hbuas2026
```

> **无需安装任何依赖**，仅需 Node.js 18+。知识库为本地 JSON 文件，断网可用。

### ⚠️ 不要直接双击 public 文件夹里的 html 文件

**这是最常见的错误。** 直接双击 `index.html` / `student.html` / `teacher.html`
会用 `file://` 协议打开，此时样式表与校徽图片全部无法加载，
页面会显示成没有格式的纯文本样子（图片位置显示为裂图）。

**必须先启动服务，再通过 `http://localhost:8080` 访问。**
如果误用了 `file://` 方式打开，页面顶部会自动显示红色提示告知正确做法。

### 三个入口

| 入口 | 路径 | 用途 |
|---|---|---|
| **入口页** | `/` | 角色选择（学生端 / 教师端）+ 会议工具入口 |
| **学生端** | `/student` | 问答：查通知、咨询办事流程、看活动 |
| **教师端** | `/teacher` | 数据看板 + 知识库维护（需口令） |
| **会议工具** | `/meeting` | 唤起 WPS、会议模板、导出知识库 |

一体机建议直接打开 `/student` 并全屏（F11），省去角色选择步骤。

### 手机端入口（二维码）

学生端侧栏会自动显示**二维码**（指向 `.studentUrl`），同学扫码即可在手机上打开，
功能与大屏完全一致——对应「大厅有终端，人人有手机端」。

服务会自动判断对外地址：
1. 设了环境变量 `PUBLIC_URL` → 用它（学院配了域名时最省事）
2. 否则用请求的 `Host`；若访问方是 `localhost`，自动替换为**局域网 IP**，方便直接分享
3. 兜底用本机第一个局域网 IP

启动窗口也会直接打印可分享的网址：

```
★ 分享给同学（需在同一网络）：
  http://192.168.1.2:8080/student
```

> 单机使用时那个 IP 也可能是 `localhost` 或虚拟网卡地址，
> 以启动窗口打印的「分享给同学」那行为准。

### 会议工具（唤起 WPS）

社区开会常用 WPS，入口在 `/meeting`（入口页底部也有链接）。

| 功能 | 说明 |
|---|---|
| **打开 WPS** | 一键唤起 WPS 文字 / 表格 / 演示 |
| **会议模板** | 会议纪要、签到表、策划方案、值班表（CSV，WPS 直接编辑） |
| **导出知识库** | 把通知/活动/FAQ/场所导成表格，开会查阅或打印 |

**技术说明（重要）**：浏览器出于安全限制**不能直接启动本机程序**。
本项目用两条路实现：

1. **URL 协议**（`ksowps://` / `ksoet://` / `ksowpp://`）——纯前端，
   点击后系统会弹一次「是否打开」确认，这是正常行为。
2. **本机接口** `/api/launch`——兜底，**仅允许 127.0.0.1 访问**。
   这一点是硬性安全要求：服务默认监听 `0.0.0.0`（同学要从手机访问），
   若此接口不限制来源，同网段任何人都能远程在你的电脑上启动程序。

> **远程访问时这些功能不可用**（页面会显示提示）。
> 必须在一体机上用 `http://localhost:8080/meeting` 打开。

> **CSV 导出已加 UTF-8 BOM**，否则 WPS/Excel 打开中文会乱码——
> 这是 Windows 上 CSV 中文乱码最常见的原因。

### 怎么发给别人看

运行一次：

```bash
node scripts/share.js
```

会生成 **`分享给他人.html`**，直接发给对方（微信/QQ 传文件均可）。
对方用浏览器打开，能看到可点击的网址、可扫码的二维码、以及打不开时的排查步骤。

**关键前提：对方必须与部署机在同一网络。**

| 对方在哪 | 能否访问 |
|---|---|
| 同一 WiFi / 局域网 | ✅ 用 `http://192.168.x.x:8080/student` |
| 校园网内（一体机部署后） | ✅ 用部署机的校园网地址 |
| 校外 / 手机流量 | ❌ 需先做公网方案 |

> **对方打不开，九成是防火墙没放行。** 以管理员身份运行：
> ```bat
> netsh advfirewall firewall add rule name="15栋社区智能体" dir=in action=allow protocol=TCP localport=8080
> ```

详细方法（含校外演示方案、给老师演示的建议）见 **[如何分享给他人.md](如何分享给他人.md)**。

### 部署到校园网

**详见 [部署指南.md](部署指南.md)**，包含三种方式（校园网内机器 / 公网临时演示 / 云平台）
以及防火墙放行、静态 IP、开机自启、ICP 备案注意事项。

部署到新机器后，先跑一次部署自检：

```bash
node scripts/deploycheck.js
```

它会检查服务监听、端口占用、防火墙、IP 是否动态、教师端口令等，
并对每个问题给出**可直接复制的修复命令**。

### 部署到社区一体机

1. 把整个 `hbwl-15-community-agent` 文件夹拷到一体机
2. 安装 Node.js 18+（[官网下载](https://nodejs.org)）
3. 双击 **`启动.bat`**（或执行 `node server.js`）
4. 浏览器访问 `http://localhost:8080/student`，按 `F11` 全屏
5. **以管理员身份放行防火墙**，否则其他机器访问不了：
   ```bat
   netsh advfirewall firewall add rule name="15栋社区智能体" dir=in action=allow protocol=TCP localport=8080
   ```
6. 设置开机自启（见部署指南第 5 节）

## 二、角色与功能

### 学生端

| 能力 | 说明 | 示例问法 |
|---|---|---|
| **查通知** | 学校/学院通知、资助认定、安全提醒 | 「最近有什么通知」 |
| **答疑问** | 41 条高频 FAQ，覆盖办事流程 | 「学生证丢了怎么补办」 |
| **看活动** | 学院活动、志愿服务、招募信息 | 「最近有什么活动可以报名」 |
| **找服务** | 报修、心理、资助、住宿、教务、图书馆 | 「宿舍东西坏了怎么报修」 |
| **查电话** | 各部门联系方式、紧急求助 | 「学校的报警电话是多少」 |
| **紧急通道** | 诈骗/火灾/急救等给出固定处置流程 | 「我已经被诈骗了怎么办」 |

### 教师端

| 模块 | 说明 |
|---|---|
| **数据看板** | 知识库健康度、累计提问、高频问题 Top 10、**待补充问题**、意图分布、学生反馈满意度 |
| **待补充问题** | **点一下即可补充答案**——问题自动填好，写完保存立即生效 |
| **待确认** | 列出所有 `verified:false` 条目，一键跳转核实 |
| **内容管理** | 通知 / 活动 / FAQ / 场所的增删改，含溯源校验 |
| **数据来源** | 13 个官方来源清单，以及未能核实内容的说明 |

> **「待补充问题」是教师端最有价值的模块**，它把维护工作闭环了：
> 同学问的问题智能体答不上来 → 自动进入清单 → 点「补充答案」→
> 问题已预填、关键词已抽好 → 只写答案 → 保存 → **同学下次问就能得到回答**。
>
> 清单收录三种缺口：
> - **未命中**——智能体完全答不上来
> - **可能答错**——给了回答但置信度低（如「校车几点发车」被答成「宿舍几点熄灯」）
> - **被点没用**——同学明确反馈没解决
>
> 按缺口强度排序（被点没用权重最高，因为那是"答了但错"，比"没答"更需要修）。

## 三、技术方案

### 为什么选择离线检索

社区一体机的实际约束是：**可能没有稳定外网、没有 GPU、交付后需要长期免维护**。

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯大模型 API | 回答灵活 | 需外网+API Key+费用；断网即废；**可能编造办事流程** | ✗ 不适合 |
| 向量检索 | 语义泛化好 | 需模型文件与算力；中文小语料收益有限 | ✗ 过重 |
| **BM25 关键词检索** | 零依赖、毫秒级、可解释、断网可用 | 不懂同义改写 | **✓ 采用** |

对社区服务场景，**准确性比灵活性更重要**——一个编造的办事流程会让同学白跑一趟。
离线检索的每条回答都可追溯到具体知识条目与官方来源。

**关于大模型（如实说明）**：当前版本**完全离线运行，不调用任何大模型**。

代码中保留了 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` 三个配置位，
以及 `stats()` 里的 `llmEnabled` 标志，但**没有任何代码真正发起过大模型请求**——
设置 `LLM_API_KEY` 只会让状态显示为「已启用」，**不会改变任何回答行为**。

之所以保留这些位置，是为了后续接入时不改动调用方。
是否需要接入、怎么接入、成本与风险，见 **[人工智能接入说明.md](人工智能接入说明.md)**。

### 为什么用 JSON 文件而不是数据库

知识库就是 `data/` 下几个 JSON 文件，**用记事本就能改**——这是刻意的选择。

| 考量 | JSON 文件 | 数据库 |
|---|---|---|
| 学院自行维护 | 记事本即可 | 需写 SQL 或开发后台 |
| 部署 | 拷贝文件夹就能跑 | 需装服务、配账号、定备份策略 |
| 备份迁移 | 复制 `data/` 即可 | 门槛较高 |
| 并发编辑 | **会互相覆盖**（当前短板） | 有事务保证 |
| 大数据量检索 | 全量遍历 | 索引加速 |

**实测数据**（`node scripts/benchmark.js`）：当前 62 条，读取+解析约 2–3 ms；
单次问答 112 µs，单进程约 8900 次/秒。**瓶颈远未触及。**

社区智能体的真实风险不是"性能不够"，而是"没人会维护"。
完整分析、换库时机与迁移方案见 **[数据库说明.md](数据库说明.md)**。

> **当前已知限制**：知识库写入是「整文件读 → 改 → 覆盖」，
> 两位老师**同时**点保存会互相覆盖。建议约定单人维护，或改前先刷新。

### 检索实现

中文没有空格分词，采用**字符二元组（bigram）为主、单字为辅**：

```
「自习室怎么预约」
  → 二元组：自习 习室 室怎 怎么 么预 预约   （主要信号）
  → 单字：  自 习 室 怎 么 预 约            （辅助召回，权重 ×0.25）
```

**关键调优**：单字必须降权。否则「今天天气怎么样」会因「怎/么/样」匹配到
「自习室可以占座吗？东西放在座位上会**怎样**」而被误判。
降权后无关问题得分从 8.41 降到 1.18，与正常问题（3.4 以上）形成清晰空档，
据此标定置信度阈值 `2.0`。

### 意图路由

三级处理：

1. **紧急通道**——仅匹配**已发生的受损事实**（被骗、着火、受伤）与**明确求助动作**（救命、快报警）
2. **列表通道**——「最近有什么活动」走活动清单，优先于 FAQ 检索
3. **检索通道**——BM25 检索，置信度不足则走兜底引导

### 关于「句式相似但主题不同」的问题（重要说明）

有一类问题词面检索无法可靠处理，例如：

| 提问 | 检索到的条目 | 问题 |
|---|---|---|
| 怎么办理校园卡 | 图书馆怎么借书 | 靠「校园卡」三字命中，主题不同 |
| 校车几点发车 | 宿舍几点熄灯 | 「几点」命中，主题完全不同 |
| 食堂几点开门 | 图书馆开放时间 | 「几点/开放时间」命中 |
| 宿舍可以养猫吗 | 能不能用吹风机 | 「宿舍/可以/吗」命中 |

本项目**实测过两种更复杂的判据，都因误伤正常问题而放弃**：

- **优势比**（Top1 领先 Top2 的幅度）：正常问题可低至 0.015，缺口问题可高达 0.80，分布重叠
- **主题词整词覆盖**：正常问题误判 2/25（「学校的校历在哪看」被误拦），
  且「四六级报名时间」被误标为缺口

**最终采用「低置信度标记」而非硬拦截。** 用 10 个正常问题 + 8 个真实缺口问题实测得分：

| 类别 | 得分范围 |
|---|---|
| 正常问题 | **35.91 ~ 70.77** |
| 缺口问题 | **7.86 ~ 24.80** |

中间有 11 分空档，因此低置信度阈值定为 **30**，实测 **18/18 零误判**：

- 得分 < 2.0 → 走兜底，明确说「没找到」
- 得分 < 30 → 正常回答，但**标注「可能不完全对应你的问题」**，并计入教师端待补充清单
- 得分 ≥ 30 → 正常回答

> 为什么不直接拦截？因为低分回答里往往有相邻的有用信息。
> 给出回答 + 标明不确定，比一句「我不知道」更有用——
> 后者会让同学以为知识库里什么都没有。
>
> **判断准不准最终靠同学的「👎 没用」反馈，算法只负责提示。**

教师端的「待补充问题」清单收录三种缺口（未命中 / 可能答错 / 被点没用），
每条都能点「补充答案」直接创建 FAQ，形成维护闭环。

| `node scripts/synccheck.js` | 数据同步回归（需服务在运行） | 改动教师端写入逻辑后 |
| `node scripts/featurecheck.js` | 新功能回归，13 项（需服务在运行） | 改动问答/反馈/活动逻辑后 |
| `node scripts/gapcheck.js` | 待补充问题闭环，8 项（需服务在运行） | 改动教师端维护流程后 |
| `node scripts/wpscheck.js` | WPS 会议工具，14 项（需服务在运行） | 改动会议工具后 |
| `node scripts/deploycheck.js` | 部署自检，含可直接复制的修复命令 | 部署到新机器时 |
| `node scripts/encodingcheck.js` | 编码完整性检查 | 用命令行工具改过文件后 |
| `node scripts/benchmark.js` | 容量基准，判断是否需要换数据库 | 每学期一次 |
| `node scripts/backup.js` | 创建备份 / `--list` 查看 / `--restore <名称>` 恢复 | **每次改内容前** |
| `node scripts/share.js` | 生成「分享给他人.html」 | 要发给别人看时 |
| `node scripts/qrcheck.js` | 用独立解码器验证二维码可扫 | 改动 `lib/qrcode.js` 后 |

> `qrcheck.js` 需要 Python 3；没有 Python 时会自动跳过并提示，**不影响程序运行**。

> **关于编码**：本项目所有文本文件使用 **UTF-8**，唯一例外是 `启动.bat`（刻意用 GBK——
> Windows 批处理的原生编码，用 UTF-8 会导致中文乱码甚至执行出错）。
> 在 Windows 上用 PowerShell 改文件时务必加 `-Encoding UTF8`，否则可能把中文写成乱码；
> 改完跑一次 `encodingcheck.js` 即可确认。

## 五、教师端使用

### 登录

访问 `/teacher`，输入口令（默认 `hbuas2026`）。
会话令牌保存在浏览器 `sessionStorage`，8 小时过期，关浏览器即失效。

**部署后请立即修改口令**：编辑 `data/_config.json` 的 `teacherPin`，
或用环境变量 `TEACHER_PIN` 指定。

### 发布通知

教师端 →「通知公告」→「+ 新增」，填写标题、分类、正文、检索关键词。

> **检索关键词是命中率的关键。** 例如「报修」这条把「微后勤、漏水、灯、门锁、断电」
> 都写进关键词，同学用哪种说法都能问到。

也可以直接编辑 `data/notices.json`：

```json
{
  "id": "n009",
  "title": "期末考试安排公布",
  "category": "教学通知",
  "date": "2026-10-20",
  "publisher": "计算机工程学院教务办",
  "priority": "high",
  "pinned": true,
  "deadline": "2026-10-25",
  "verified": true,
  "sourceId": "s009",
  "tags": ["考试", "期末", "安排"],
  "content": "期末考试安排已公布，请同学们登录教务系统查询…"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✓ | 标题，检索权重最高 |
| `content` | ✓ | 正文 |
| `verified` | ✓ | **`true` 表示已核实**（须填 `sourceId`）；`false` 显示「待确认」徽章 |
| `sourceId` | 条件 | `verified:true` 时必填，须存在于 `sources.json` |
| `tags` | | **检索关键词**，同学可能用到的说法都放进来 |
| `pinned` / `deadline` | | 置顶 / 截止日期 |

### 审核待确认内容

教师端 →「待确认」→ 点「去核实」→ 编辑内容 → 把「核实状态」改为**已核实**
→ 填写**来源编号**（如 `s008`）→ 保存。

> 系统会强制校验：标为「已核实」必须有有效 `sourceId`，否则拒绝保存。
> 这是防止「把编造内容伪装成官方信息」的机制。

### 看板数据从哪来

同学每次提问都会记录到 `data/_logs/queries-YYYY-MM-DD.jsonl`，
教师端看板据此统计高频问题与未命中问题。

> **隐私说明**：日志只记录问题原文与意图分类，**不记录任何身份信息**
> （无 IP、无学号、无会话 ID）。可在教师端清空日志，或直接删除 `data/_logs/` 目录。

### 备份与恢复（重要）

**教师端的删除是不可撤销的**——整文件覆盖写，没有版本历史。
误删一条通知或改坏内容，没有备份就找不回来。**改内容前先备份。**

```bash
node scripts/backup.js                      # 创建备份
node scripts/backup.js --list               # 查看已有备份
node scripts/backup.js --restore backup-20261018-120000   # 恢复
```

- 备份保存在 `backups/` 目录，按时间戳命名，自动保留最近 30 份
- 备份内容是 `data/` 下所有 JSON（不含问答日志）
- **恢复前会自动把当前状态另存一份**，恢复错了还能回头

> 建议：每次批量改通知/活动前跑一次备份，或每周固定备份一次。

### 自检

改动知识库或代码后运行：

```bash
node scripts/selfcheck.js       # 问答与溯源，49 项
node scripts/featurecheck.js    # 新功能回归，13 项（需服务在运行）
node scripts/synccheck.js       # 数据同步，8 项（需服务在运行）
```

覆盖事实问答、意图路由、边界处理、**数据溯源完整性**、
活动状态计算、教师端发布、学生反馈、电话拨号等。

### 开机自启（Windows 一体机）

**任务计划程序**（推荐）：

1. 「任务计划程序」→「创建任务」
2. 常规：勾选「不管用户是否登录都要运行」「使用最高权限运行」
3. 触发器：新建 →「登录时」
4. 操作：启动程序
   - 程序：`node.exe` 完整路径（如 `C:\Program Files\nodejs\node.exe`）
   - 参数：`server.js`
   - 起始于：`C:\path\to\hbwl-15-community-agent`
5. 设置：勾选「如果任务失败，按以下频率重新启动」
